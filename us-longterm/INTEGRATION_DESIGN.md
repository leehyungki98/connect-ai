## 1. 편입 후 connect-ai 구조

```
connect-ai/                      # 기존 자체 git 저장소 (github.com/leehyungki98/connect-ai)
├── DESKS.md                     # [신설] §3 초안 그대로
├── .gitignore                   # [수정] us-longterm/state/ · us-longterm/.env 두 줄 추가
├── trading/                     # 스윙팀 — 파일 단위 무수정 (읽기만 허용)
└── us-longterm/                 # [신설] 미국주식 장기 데스크
    ├── CLAUDE.md                # BUILD_MISSION §8 초안 (경로만 이 구조로 치환)
    ├── README.md
    ├── BUILD_MISSION.md         # 빌드 지침 원본 (완료 후 참고 문서로 유지)
    ├── INTEGRATION_DESIGN.md    # 이 문서 (의사결정 기록)
    ├── requirements.txt         # yfinance, pandas, pytest — 스윙과 환경 공유하지 않음
    ├── longcore/                # config.py·safety/·gates/·data/·portfolio/·rebalance/·paper/
    ├── scripts/                 # run_daily / run_rebalance / run_report / run_backtest
    ├── state/                   # git 제외 (운영 데이터)
    ├── ledger/                  # git 추적 — 기존 Long-term_trader/ledger 그대로 이전
    └── tests/                   # 전부 오프라인
```

연쇄 효과 없는 이유: `trading/` 과 `us-longterm/` 은 서로 import 하지 않고,
모듈명(`autotrader` vs `longcore`)·스크립트 실행 위치(각 폴더 루트)·state 가 전부 분리된다.
루트에서 바뀌는 파일은 정확히 2개(DESKS.md 신설, .gitignore 2줄)다.

## 2. BUILD_MISSION.md 개정 (승인 시 반영)

편입 결정과 충돌하는 조항만 고친다. 나머지(파라미터·모듈 스펙·비범위)는 전부 유지.

| 위치 | 현행 | 개정 |
|---|---|---|
| §1-3 | "별도 git 저장소, 별도 state. `connect-ai/` 어떤 파일도 읽기 외 접근 금지" | "connect-ai 저장소 내 `us-longterm/` 폴더. **`trading/` 폴더 무접촉**(읽기만). 두 데스크 간 코드 공유·import·복붙 금지는 그대로. 루트 변경은 DESKS.md·.gitignore 로 한정" |
| §2 | 루트가 `Long-term_trader/`, "`git init` 하고 첫 커밋까지" | 루트가 `connect-ai/us-longterm/`, git init 삭제 — connect-ai 저장소에 커밋. `.gitignore` 는 루트에 `us-longterm/state/`·`us-longterm/.env` 추가 (trading 관례와 동일) |
| §7-6 (DoD) | "`connect-ai/` 무변경 — git status 깨끗함 확인" | "`trading/` 무변경 + 루트 변경이 DESKS.md·.gitignore 2건뿐임을 `git status`/`git diff --stat` 출력으로 확인" |

## 3. DESKS.md 초안 (connect-ai 루트, 승인 시 이 내용으로 생성)

```markdown
# DESKS — 트레이딩 데스크 조직

모의투자 전용 워크스페이스. 각 데스크는 독립 조직이다.

## 데스크 목록

| 데스크 | 폴더 | 시장 | 스타일 | 체결 | LLM |
|---|---|---|---|---|---|
| 스윙 | `trading/` | 한국 주식 | 일봉 스윙 (~10거래일) | KIS 모의투자 API | codex 공격 / claude 방어 |
| 장기 | `us-longterm/` | 미국 주식 | 코어 장기 (분기 리밸런싱) | 내부 페이퍼 엔진 | 없음 (판단은 코드 밖 절차) |

## 자금 배분 (모의, 2026-07-20 사용자 승인 — 이 표가 단일 출처)

- 스윙 25% = 1,000만원 / 장기 75% = 3,000만원 (KRW 환산 기준)
- 변경은 사용자 승인 후 이 파일에서만 수정하고 각 데스크에 반영한다.

## 상호 규칙

1. 데스크 간 코드 공유·import·복붙 금지. 패턴(킬스위치·게이트·state/ledger 구분)은
   철학으로만 공유하고 구현은 각자 소유한다.
2. 서로의 폴더를 수정하지 않는다 (읽기만 허용).
3. 킬스위치·안전층·state 는 데스크별 독립 — 한쪽 차단이 다른 쪽에 전파되지 않는다.
4. 공통 헌법: 안전층은 100% 결정적 코드(LLM 금지), 실거래 연결 금지,
   "완료/검증됨" 보고 전 실제 테스트 출력 첨부, 전략 변경은 검증 + 사용자 승인 후에만.
5. 새 데스크 추가 시: 이 표에 등록 → 자금 배분 재승인 → 별도 폴더 신설.
```

## 4. 승인 후 빌드 순서

1. `git -C connect-ai status` 로 깨끗한 기준선 확인 (아니면 사용자에게 먼저 보고)
2. 루트 커밋 ①: DESKS.md 신설 + .gitignore 2줄
3. `us-longterm/` 뼈대 생성, `Long-term_trader/ledger/`·BUILD_MISSION·이 문서 이전 → 커밋 ②
4. BUILD_MISSION 대로 빌드 (개정 §2 경로 기준) — 커밋 단위는 모듈별
5. DoD 7항 검증 (개정 §7-6 포함) → 결과 출력 첨부해 보고
6. 검증 통과 후 `Desktop/agent/Long-term_trader/` 원본 폴더 제거 (agent 루트 저장소에는
   원래 untracked 였으므로 git 조작 불필요)

## 5. 설계 검증 체크 (통합 전 확인한 사실)

- connect-ai 는 자체 저장소이며 agent 루트 저장소에서 `/connect-ai/` 로 ignore 됨
  → 편입해도 중첩 저장소 문제 없음 (확인: agent/.gitignore)
- 루트 .gitignore 에 `trading/state/`·`trading/.env` 관례 존재 → 동일 패턴 확장
- `autotrader` / `longcore` 모듈명 충돌 없음, conftest.py·pytest 실행도 폴더별 독립
- 스윙의 auto-git-sync(_safeGitAutoSync)는 brain 폴더 대상이라 us-longterm 과 무관

## 6. 조직 설계 — CEO · 총괄팀장 · 실무 에이전트 · 비서 (2026-07-20 추가)

### 조직도

```
사용자 (오너 — 모든 승인권)
│ 지휘 라인: 사용자 → CEO → 총괄팀장      보고 라인: 총괄팀장 → 비서 → 사용자
│
├── CEO — 업무 분배·우선순위, 데스크 간 조율, 자금배분 "제안", 보고 취합
│   ├── 스윙팀 총괄팀장 (trading/ — 기존 파이프라인 관리, 코드 무수정)
│   └── 미장팀 총괄팀장 (us-longterm/) — 분기 리뷰 오케스트레이션, 산출물 취합
│       ├── 선정자 (codex, 공격): 분기 편입 후보 데이터 수집 + 3기준 판정 초안
│       ├── 판정자 (claude, 방어): 선정자 논지 반박·검증 — 다른 모델 = 교차검증
│       ├── 정세분석가 (리서처): 뉴스·매크로·지정학 모니터링 — 출구 제한 규칙 아래
│       ├── 코더: 코드 변경 제안 (편집금지구역 제외) + 테스트 출력 첨부
│       └── 사후분석가: 일일 NAV vs SPY 해석, 분기 리포트, ledger 기록
└── 비서 — 각 총괄팀장에게 전 사항 보고받아 사용자 전달 (secretary/bot.py 텔레그램 재사용)
```

### 팀 성격 차이 (2026-07-20 사용자 방향 확정)

스윙팀은 일봉·수급 기계 — 뉴스를 보지 않는 것이 설계다. 미장팀은 "회복 전제"에
베팅하는 구조라 그 전제를 흔드는 세계(뉴스·증시 분위기·지정학)를 알아야 한다.
단, **정보의 출구를 3개로 제한**한다:

1. 분기 리뷰의 질적 리스크 서술 (예: TSM 지정학 리스크 변화 → 논지에 기록)
2. 사후분석 해석 (NAV 변동의 배경 설명)
3. 긴급 보고 → **사용자의** 킬스위치 판단 (전쟁·상폐급 이벤트 시 비서 경유 즉시 보고.
   손절 없는 구조의 유일한 비상구에 "당길지 검토할 눈"을 붙인다 — 당기는 손은 사용자)

**금지 출구**: 리밸런싱 타이밍·비중·주문에 뉴스/정세를 반영하는 모든 경로.
허용되는 순간 타이밍 전략으로 변질 — 헌법(손절 없음·모멘텀 금지) 위반이다.

### 경계선 (기존 헌법과의 정합 — 위반 불가)

1. **체결 경로에 에이전트 금지.** 미장팀 매매(분기 리밸런싱)는 결정적 코드가 전부.
   선정자·판정자의 무대는 분기 리뷰(편입/퇴출 **제안**)이지 주문이 아니다.
   BUILD_MISSION §9 "LLM 기반 판단 로직 금지"는 그대로 유효 — 조직은 코드 밖 절차다.
2. **CEO 권한은 제안·조율 + 전결 화이트리스트까지.** 전결 범위(2026-07-20 사용자 승인):
   ① 읽기 전용 실행(리포트 재생성·데이터 재검토 지시) ② 조사 태스크 배분(결과는
   제안서로만) ③ 주문 없는 정기 스크립트 실행(run_daily 등, 운영 로그 적재).
   "소규모인가"를 CEO가 판단하지 않는다 — **이 목록에 있는 것만** 전결, 결과는 비서
   경유 사후 보고. 코드·설정·전략 변경, 리밸런싱 실행, 자금배분은 항상 사용자 승인.
   자동 승인 없음 (스윙 승인 철학과 동일).
3. **스윙팀 무접촉.** 스윙팀장 역할은 DESKS.md 조직도에 기록만, trading/ 코드 무수정.
4. **에이전트 산출물의 종착지는 승인 카드.** 승인 전에는 코드·구성 어디에도 반영 안 됨.

### 구현 수위 (단계적 — 2026-07-20 사용자 확정)

- **지금(편입 시)**: 문서+절차만 — DESKS.md에 조직도·권한 경계, 미장팀 CLAUDE.md에
  팀 내 역할 규정. 실행은 "역할대로 세션을 돌리는 절차" (분기 리뷰 시 선정자→판정자 순).
- **자동화 도입 게이트** (스케줄·자동 소집·비서 자동 보고 — 전부 아래 통과 후에만):
